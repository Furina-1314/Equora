# Windows 日程规划与专注软件——完整开发提示词

> 使用方式：将本文完整提供给编码模型或开发团队。本文是产品需求、架构约束、开发路线、验收标准和最终交付要求的统一来源。除非用户明确修改要求，否则不得擅自删减核心功能、改变技术栈或以演示代码代替可发布实现。

## 1. 角色与总目标

你是一名资深 Windows 桌面软件架构师、C++/C# 工程师、产品设计师、数据库与同步系统工程师。你的任务是从零开发一款面向 Windows 10 1809 及以上、重点适配 Windows 11 的现代日程规划与专注软件，中文名为“衡序”，英文名为“Equora”。

软件应覆盖完整闭环：

1. 快速收集任务与想法。
2. 判断优先级和重要性。
3. 将任务安排到日历时间块。
4. 创建专注环境并执行任务。
5. 温和或严格地限制分心应用和网站。
6. 记录计划时长、实际时长、中断和完成情况。
7. 基于历史数据进行每日、每周复盘和智能建议。
8. 在单设备离线状态下完整工作，并逐步支持安全可靠的多设备云同步。

最终目标不是制作原型，而是完成一款可安装、可升级、可恢复、可测试、可长期使用的正式软件。开发过程必须按里程碑持续推进，每个阶段都要得到可运行构建，不允许长期停留在不可集成的分支或仅有界面占位符的状态。

## 2. 核心产品原则

- 本地优先：没有账号、没有网络、没有服务器时，核心功能仍然完整可用。
- 数据安全：任何计划、任务、笔记和统计不得因崩溃、断电、升级或同步冲突而静默丢失。
- 单一事实源：日历、列表、四象限和专注界面展示的是同一批任务，不建立互不一致的重复数据。
- 快速操作：用户应在数秒内记录任务，在几分钟内安排一天，并随时看清“现在做什么、下一件是什么、今天是否过载”。
- 渐进式复杂度：默认界面简洁，高级同步、自动化、依赖关系和强限制功能按需展开。
- 可解释智能：自动排程和智能建议必须显示原因、允许预览、撤销和关闭，不能未经允许大规模修改日程。
- 隐私优先：专注分析默认仅在本地进行；禁止键盘记录、屏幕截图、聊天内容采集和文档内容扫描。
- 可恢复限制：所有应用或网站限制必须提供安全白名单、紧急解锁、崩溃恢复和自动解除机制，绝不能把用户锁在系统之外。
- 原生 Windows 体验：遵循 Fluent Design、Windows 键盘和鼠标交互、无障碍、高 DPI、深浅色主题和系统窗口行为。

## 3. 固定技术栈

### 3.1 桌面前端

- C# 与当前稳定版 .NET。
- WinUI 3、XAML、Windows App SDK Stable。
- CommunityToolkit.Mvvm 实现 MVVM。
- 前端只负责界面、展示状态、导航、动画、无障碍和平台交互，不承载核心业务规则。
- 使用 MSIX 作为主要安装与升级方式；需要安装 Windows Service 时设计受控的附加安装流程。

### 3.2 本地核心

- C++20。
- CMake 管理纯 C++ 模块，vcpkg 管理原生依赖。
- SQLite 作为客户端本地数据库。
- C++核心负责领域模型、数据库、重复任务、冲突检测、智能排程、同步引擎、专注规则和统计分析。
- 使用 GoogleTest 或等价成熟框架进行 C++ 单元测试。

### 3.3 C# 与 C++ 互操作

- 第一选择：稳定 C ABI + .NET `LibraryImport`/P/Invoke。
- 仅在大量复杂对象、事件和回调使 C ABI 明显不可维护时，才允许增加一层很薄的 C++/CLI DLL。
- 禁止使用 C++/CLI 开发整个应用或 WinUI 前端。
- 禁止跨 ABI 直接暴露 `std::string`、STL 容器、C++异常、智能指针或C++类。
- 使用不透明句柄、UTF-8字符串、固定布局DTO、字节数组、错误码和显式释放函数。
- 谁分配内存，谁负责释放；所有原生返回缓冲区必须有配套释放API。
- C++异常必须在边界内捕获并转换为稳定错误对象。
- 日历查询、批量更新等使用粗粒度批量接口，避免每个任务一次跨语言调用。

### 3.4 云端同步服务

- C++20 + Drogon 构建 REST/JSON API。
- PostgreSQL 作为正式服务端数据库。
- Docker 构建与部署；开发阶段允许在 Windows Docker Desktop 或本机进程运行。
- 生产环境通过反向代理终止 HTTPS；数据库端口不得暴露给桌面客户端或公网。
- 客户端只访问 HTTPS API，绝不直接连接 PostgreSQL、MySQL 或 SQL Server。
- 本地个人服务器模式可通过 Tailscale 私有网络访问 API，不要求公网端口转发。

### 3.5 专注限制组件

- 普通限制与活动检测：C++用户态模块。
- 后期严格限制：独立 C++ Windows Service，通过命名管道与桌面应用通信。
- 网站限制：Edge/Chrome Manifest V3 扩展，使用 TypeScript/JavaScript 和 `declarativeNetRequest`，通过 Native Messaging 与桌面程序通信。
- Windows Filtering Platform 仅作为后期可选增强，默认不开发内核驱动。
- 不使用修改 `hosts` 文件作为正式网站限制方案。
- 不使用 AppLocker、WDAC 作为普通用户频繁切换的专注限制机制。

## 5. 核心数据模型

所有主要实体从第一天起使用 UUID，不使用仅在本机有意义的自增ID作为跨设备标识。所有时间统一以 UTC 存储，在展示层按用户时区转换；日历全天事项还应保留本地日期语义，避免跨时区后错误移动。

主要实体至少包括：

- User：用户账户与同步身份。
- Device：设备ID、名称、最后同步时间和撤销状态。
- Calendar：日历名称、颜色、来源和可见性。
- Project：项目、状态、目标和归档信息。
- Task：标题、说明、状态、优先级、重要性、截止时间、预计时长、实际时长、精力要求、上下文和项目。
- TaskDependency：前置、后置和阻塞关系。
- ChecklistItem：任务内部检查项。
- Tag：标签及颜色。
- TaskTag：任务与标签关系。
- TimeBlock：任务在日历中的计划时间段。
- Event：非任务型日程、会议和全天事项。
- RecurrenceRule：重复规则和例外日期。
- FocusSession：专注模式、开始结束、暂停、中断和结果。
- Interruption：中断时间、原因、来源和处理方式。
- DistractionInboxItem：专注期间快速记录的稍后事项。
- FocusProfile：允许/限制的应用、网站、通知、计时方式和强度。
- AppUsageRecord：应用标识、开始结束时间和分类，不记录输入内容。
- WebsiteRule：域名、路径规则、白名单、预算和生效范围。
- DailyReview、WeeklyReview：复盘结果和下阶段重点。
- AttachmentReference：附件引用和本地/云端状态。
- AutomationRule：触发器、条件、动作、启用状态和执行日志。
- SyncOutbox：待上传操作。
- SyncState：服务端游标和最后成功同步时间。
- ChangeLog：服务端有序变更流。

所有可同步实体至少包含：

```text
id                UUID
user_id           UUID
created_at        UTC时间
updated_at        UTC时间
revision          单调递增版本
deleted_at        可空UTC时间，表示软删除墓碑
last_device_id    最后修改设备
```

数据库必须使用版本化迁移。升级前备份，迁移失败时回滚，不允许直接删除旧库重新创建。

## 6. 日历与时间块功能

必须实现：

- 日、工作周、周、月、年、议程、时间轴视图。
- 多日历叠加、单独显示和颜色编码。
- 鼠标拖拽创建、移动和调整时间块长度。
- 待办拖入日历后转为时间块，但仍保留任务身份。
- 时间块拖回待办区时只取消排期，不删除任务。
- 多选、复制、批量移动和批量改标签。
- 全天事项、跨天任务、里程碑和倒计时。
- 当前时间线、工作时间范围、周末和非工作时间折叠。
- 时间轴缩放、吸附粒度和键盘微调。
- 冲突检测、重叠布局和过载警告。
- 计划时长与实际时长同时显示。
- 可设置任务前后准备、通勤和缓冲时间。
- 支持复杂重复规则，例如每月最后一个工作日、每两周的周二和周四、完成后若干天再次提醒。
- 支持重复实例例外：仅修改本次、修改本次及以后、修改整个系列。
- 导入和导出 ICS；后期支持 CalDAV、Outlook和Google Calendar接入。

核心周视图必须是自定义高性能时间轴，支持大量任务虚拟化。不得把所有时间块永久实例化为昂贵控件。滚动、缩放和拖拽过程中应尽量保持平滑，并在拖动时实时显示开始时间、结束时间、持续时长、冲突和工作时间范围。

## 7. 待办、项目与视图

必须实现：

- 收件箱、今天、近期、已逾期、已安排、无日期、等待中、已委派和已完成。
- 项目、分组、标签、优先级、重要性、截止日期、预计时长和精力等级。
- 子任务、检查项、任务依赖和阻塞状态。
- 自定义筛选器与智能清单。
- 保存视图、排序、分组和批量编辑。
- 任务模板、项目模板和例行流程模板。
- 附件、链接、备注、会议链接和相关文件。
- 搜索标题、说明、标签、项目、日期范围和状态。
- 归档与恢复，不默认永久删除历史项目。

同一任务可以同时出现在列表、四象限、项目和日历中，但任何视图中的修改必须立即反映到其他视图。

## 8. 四象限与决策辅助

提供标准重要/紧急四象限：

- 重要且紧急：立即处理。
- 重要但不紧急：安排时间。
- 不重要但紧急：委派或快速处理。
- 不重要且不紧急：删除、推迟或限制投入。

具体要求：

- 支持卡片拖拽切换象限。
- 截止时间和阻塞关系可生成“紧急”建议，但最终决定权属于用户。
- “重要性”由用户目标、项目和手动选择决定，AI只能建议并说明理由。
- 每个象限支持在制品数量限制和预计时长汇总。
- 第二象限卡片提供一键安排到日历的入口。
- 支持自定义矩阵，如影响力/投入成本。
- 从第一、第二象限选择“今日三件要事”。
- 四象限不是独立数据库，仅是任务查询与编辑视图。

## 9. 快速收集与自然语言输入

必须支持：

- 全局快捷键呼出快速输入框。
- 系统托盘快速添加。
- 语音输入接口预留。
- 将剪贴板文本、网页链接、文件路径和截图引用转为任务。
- 在不打开主窗口的情况下完成记录。
- 自然语言识别日期、时间、持续时长、重复、项目、标签和优先级。

示例：

```text
明天下午3点开会一小时
每周五17点提醒写周报
今晚安排45分钟复习电路
下周三前完成设计稿 #产品 !高优先级
```

解析结果必须在提交前以可编辑方式预览。解析失败时保留原始文本，绝不静默丢弃内容。

## 10. 专注会话与计时模式

日历时间块和待办都可直接启动专注会话。支持：

- 标准番茄钟和完全自定义周期。
- 60至120分钟深度工作。
- Flowtime自由计时。
- 倒计时、正向计时和无计时沉浸模式。
- 编程、写作、阅读、学习、会议等预设。
- 暂停、继续、提前完成、延长、跳过和放弃。
- 会话前目标与完成标准。
- 会话后完成度、实际时长、困难和下一步记录。
- 休息提醒、眼睛休息、补水、伸展和久坐提醒。

专注界面只展示当前任务、目标、剩余时间、必要资料、暂停/完成和分心捕获入口。提供置顶迷你窗、系统托盘状态和任务栏进度。

## 11. 分心捕获箱

提供独立全局快捷键，在专注期间弹出极小输入框，允许用户记录突然想起的事情。记录后立即关闭，不切换主界面焦点。

专注结束时将条目统一整理为：

- 新任务。
- 日程。
- 笔记。
- 添加到当前任务。
- 删除。

该功能必须保证输入内容立即持久化，即使软件随后崩溃也能恢复。

## 12. 应用访问限制

实现三个可配置等级：

### 12.1 温和提醒

- 使用前台窗口事件识别当前应用。
- 打开受限应用时显示返回专注、允许5分钟或结束会话。
- 不要求管理员权限。
- 用户可关闭此能力。

### 12.2 增加摩擦

- 再次访问时要求选择原因。
- 可加入5至30秒等待。
- 支持每日应用时间预算。
- 支持一次性临时允许。
- 不默认强制结束进程。

### 12.3 严格限制

- 仅针对用户明确选择的非关键应用。
- 后期由Windows Service实施更可靠的限制。
- 优先请求应用正常退出；强制终止必须有明确警告，避免数据丢失。
- 永远不限制系统设置、安全软件、文件管理器、辅助功能、紧急通信和恢复工具。
- 必须提供紧急解锁、自动超时、崩溃恢复和重启恢复。

禁止未经明确授权扫描窗口内容、按键、剪贴板或文档内容。

## 13. 网站访问限制

开发 Edge/Chrome 扩展，使用动态与会话规则完成：

- 域名、子域名和特定路径限制。
- 白名单优先。
- 专注会话开始时下发规则，结束时可靠撤销。
- 访问受限页面时显示当前任务、剩余时间、返回任务、临时允许和紧急解锁。
- 学习网站允许规则和娱乐网站时间预算。
- 扩展重启、浏览器升级和主程序异常后保持状态一致。
- Native Messaging消息必须有版本号、会话ID、校验和重放保护。

后期可增加 WFP 用户态过滤作为跨浏览器增强，但不得依赖解析HTTPS完整路径，也不得在未完成恢复测试前启用严格系统级网络过滤。

## 14. 专注环境预设

允许用户创建和编辑Focus Profile，例如：

- 编程：允许IDE、终端、文档和指定技术网站，限制社交媒体和游戏，自动打开项目目录。
- 写作：允许文档、参考资料和音乐，隐藏非必要窗口，进入全屏专注。
- 阅读：只保留阅读器、笔记和词典。
- 学习：允许课程网站和资料，按章节生成检查点。
- 会议：打开会议链接和材料，暂停普通任务提醒，会后提取行动项。

预设可配置允许应用、限制应用、允许网站、限制网站、计时方式、声音、休息规则、是否置顶和自动打开的资料。所有自动操作必须在首次使用时得到授权，并可单独关闭。

## 15. 活动分析与隐私

经用户主动授权后，只在本地记录：

- 前台应用标识和分类。
- 每个应用停留时间。
- 窗口切换次数。
- 系统空闲时间。
- 会话完成率和中断原因。
- 计划时长与实际时长。

默认禁止记录：

- 键盘输入和鼠标内容。
- 剪贴板内容。
- 屏幕截图。
- 文档、邮件和聊天正文。
- 完整浏览历史。
- 密码或认证信息。

分析结果包括最佳专注时段、常被低估的任务类型、主要分心来源、计划准确度、上下文切换频率、建议会话长度和工作/休息比例。所有指标必须解释计算方式，允许按天删除、全部删除和完全禁用。

## 16. 智能规划

实现可解释、可撤销的计划辅助：

- 根据截止时间、重要性、优先级、预计时长、工作时间、精力和依赖关系建议排程。
- 自动寻找连续或可拆分空闲时间。
- 识别冲突、过载、缺少休息和不可实现的截止日期。
- 为未完成任务提供保留原计划、顺延、重新规划或取消选择。
- 自动加入准备、通勤、缓冲和休息。
- 根据历史数据校正预计时长，但保留用户原始估计。
- 支持“如果今天只能完成三件事”的建议。
- 支持任务拆分和“下一步行动”建议。
- 计划变更先显示差异预览，再由用户确认。
- 一次性撤销整个自动排程操作。

第一版采用确定性规则引擎；AI能力放在可替换接口之后，不得成为离线核心功能的必需依赖。

## 17. 通知、小组件与Windows集成

实现：

- Windows应用通知，包含完成、延后、重新安排、开始专注和打开资料按钮。
- Windows小组件显示当前任务、剩余时间、下一任务、今日三件要事和快速记录。
- 系统托盘显示下一任务和专注状态。
- 全局快捷键。
- 开机启动可选，默认清晰告知。
- 文件拖入任务成为附件引用。
- 深浅色、跟随系统、强调色、高对比度。
- 多显示器、不同缩放比例、触摸和键盘操作。
- MSIX安装、升级和卸载后用户数据处理策略。

不要依赖未公开的Windows接口控制其他应用通知或虚拟桌面。对于系统勿扰，提供用户引导或正式公开API能力。

## 18. 云同步协议

客户端始终先写本地SQLite，再异步同步。一次本地业务修改和写入`SyncOutbox`必须处于同一数据库事务。

同步支持：

- Push：上传本地未确认操作。
- Pull：按服务端游标拉取增量变化。
- 幂等操作ID，重复提交不得产生重复效果。
- 删除墓碑，避免已删除内容被离线设备复活。
- `base_revision`并发检查。
- 服务端原子事务和有序变更游标。
- 指数退避、随机抖动、网络恢复后继续。
- 用户注销时安全处理尚未同步数据。
- 设备撤销和令牌轮换。

建议接口：

```http
POST /api/v1/sync
Authorization: Bearer <access-token>
```

```json
{
  "protocolVersion": 1,
  "deviceId": "uuid",
  "cursor": 18291,
  "operations": [
    {
      "operationId": "uuid",
      "entityType": "task",
      "entityId": "uuid",
      "baseRevision": 5,
      "operation": "update",
      "payload": {}
    }
  ]
}
```

响应至少返回已接受操作、拒绝原因、冲突、服务端变化和下一游标。

冲突策略：

- 不同字段修改尽可能字段级合并。
- 简单标量可采用明确的最后修改胜出规则，但必须以服务端时间与版本为准，而不是盲信客户端时钟。
- 长笔记或大量文本冲突保留两个版本供用户选择。
- 删除与修改冲突默认保留墓碑，同时允许恢复为新版本。
- 时间块冲突不能静默覆盖，必须进入冲突中心。
- 所有自动冲突处理都要保留审计信息。

禁止直接同步正在使用的SQLite文件。OneDrive、Dropbox等只能用于关闭数据库后的加密备份，不能代替记录级同步。

## 19. 单设备、本机服务器与生产部署模式

必须支持三种运行方式：

### 模式A：纯单机

- 无账号、无服务器。
- SQLite本地保存。
- 自动备份、导入和导出。
- 同步模块处于禁用状态但数据结构已准备好。

### 模式B：本机模拟服务器

- Drogon API运行在`localhost`。
- PostgreSQL运行在Docker容器或本机开发实例。
- 数据库仅绑定本机或容器内部网络。
- 用两个独立客户端配置模拟两台设备，测试冲突和离线恢复。

### 模式C：个人或正式云服务器

- 同一套Docker镜像部署到Linux服务器。
- PostgreSQL使用持久卷与自动备份。
- HTTPS、身份认证、限流、审计和健康检查。
- 个人电脑作为临时服务器时优先通过Tailscale访问API，不直接暴露数据库和管理面板。

## 20. 备份、恢复与数据可携带性

必须实现：

- SQLite一致性备份，不直接复制处于不一致状态的打开文件。
- 每日自动备份和手动备份。
- 可配置保留数量和空间上限。
- 备份校验和、版本信息和恢复预演。
- 恢复前再次备份现有数据库。
- JSON、CSV、ICS导入导出。
- 完整账户数据导出。
- 附件缺失和损坏提示。
- 云端PostgreSQL定期备份与恢复演练。

应用崩溃、数据库迁移失败、磁盘空间不足和同步失败时，必须提供可理解错误信息与安全恢复路径。

## 21. UI与交互设计

采用Fluent Design，但不为视觉效果牺牲信息密度和操作效率。

主窗口建议为：

```text
左栏：导航、日历、项目、标签、智能清单
中栏：日历、任务列表、四象限或统计主视图
右栏：任务详情、子任务、备注、附件和活动记录
```

要求：

- 右栏可收起，中栏可最大化。
- 紧凑、标准、宽松三种密度。
- 命令面板统一搜索任务、项目、页面和操作。
- 主要操作均支持鼠标与键盘。
- 拖拽过程中提供清晰预览和可撤销反馈。
- 颜色有稳定语义，并通过图标、文字或形状提供非颜色冗余。
- 支持色盲友好、高对比度和屏幕阅读器。
- 焦点顺序、快捷键和可访问名称必须完整。
- 动画遵循系统“减少动画”设置。
- 破坏性操作需要确认或可撤销，不使用仅有“确定”的模糊对话框。

默认快捷键建议：

```text
Ctrl+N                  新建任务
Ctrl+Shift+Space        全局快速记录/分心捕获
Ctrl+K                  命令面板
T                       回到今天
Space                   开始或暂停专注
Enter                   编辑当前项目
Ctrl+Z                  撤销
Ctrl+Shift+Z            重做
```

允许用户重新绑定快捷键，并检测与系统或其他程序的冲突。

## 22. 自动化规则

实现安全、可预览、可追踪的自动化系统：

- 触发器：任务创建、标签变化、临近截止、进入时间段、完成、延期、专注开始/结束、同步完成。
- 条件：项目、标签、优先级、时间、工作日、设备、预计时长、精力等级。
- 动作：添加标签、设置提醒、安排时间、创建子任务、启动专注预设、发送自身通知。
- 防止递归触发和无限循环。
- 提供执行日志、失败原因、禁用和测试运行。
- 自动化修改可撤销；影响多个任务时必须预览。

示例：

- 带“会议”标签的任务提前15分钟提醒。
- 超过2小时的任务建议拆分。
- 连续工作90分钟后建议休息。
- 任务延期时重新评估后续依赖。

## 23. 每日与每周复盘

每日复盘包括：

- 今日完成、延期和取消事项。
- 计划与实际时长差异。
- 今日三件要事完成情况。
- 分心次数和主要来源。
- 明日未解决事项。

每周复盘包括：

- 项目进展和里程碑。
- 时间分配、深度工作和休息比例。
- 估时准确度。
- 经常延期的任务类型。
- 最佳专注时段。
- 下周目标与容量建议。

统计必须帮助决策，不使用带羞辱感的文案，不制造虚假的精确评分，不用连续签到绑架用户。

## 24. 安全要求

- 不在源码、桌面配置或日志中硬编码数据库密码、令牌和私钥。
- 桌面令牌使用Windows安全存储或DPAPI保护。
- 服务端密码使用成熟的现代密码哈希方案，密钥可轮换。
- 所有网络通信使用HTTPS，开发环境证书也应有明确配置。
- API进行输入校验、鉴权、资源所有权检查、限流和审计。
- 日志默认脱敏，不记录任务正文、访问令牌、密码或完整个人数据。
- 浏览器扩展申请最小权限，并明确解释权限用途。
- Windows Service使用最小权限账户，IPC进行调用方验证。
- 数据导出、账号删除和设备撤销必须可用。
- 对第三方依赖进行许可证清单、版本锁定和漏洞扫描。

## 25. 性能与可靠性目标

在明确记录的参考设备与数据规模下，以发布构建测量：

- 冷启动到主窗口可交互：目标不超过1.5秒，低端设备不超过3秒。
- 空闲CPU：平均低于1%。
- 非专注状态后台不进行高频轮询。
- 常规空闲内存：目标低于250MB，并持续监测泄漏。
- 日历滚动、缩放和拖拽：目标55 FPS以上，避免明显卡顿。
- 本地任务新增与编辑提交：P95低于100毫秒。
- 一万条任务和五万条时间记录下，主要视图仍可正常使用。
- 数据库写入使用事务；崩溃后不得出现半个业务操作。
- 同步操作可安全重试，重复请求不得产生重复数据。
- 所有后台线程、计时器、回调和原生句柄在退出时正确释放。

如果目标未达到，必须先测量、定位瓶颈，再优化；不得通过删除正确性检查或关闭持久化换取表面速度。

## 28. 开发代理工作方式

每轮开发都必须：

1. 先阅读现有代码、文档、迁移和测试，不盲目重写。
2. 明确本轮目标、依赖、风险和验收条件。
3. 优先交付纵向可运行切片，而不是只堆接口或只画界面。
4. 保持现有用户数据和API兼容；任何破坏性变化必须提供迁移。
5. 实现功能的同时补充测试、日志、错误处理和文档。
6. 运行相关构建、静态检查和测试，记录实际结果。
7. 更新`docs/progress.md`，写明已完成、未完成、已知问题和下一步。
8. 不伪造运行结果，不声称未验证的功能已经完成。
9. 遇到产品决策不明确时，选择最安全、可逆、符合本地优先原则的默认值，并记录假设。
10. 不因为追求“一次完成全部功能”而牺牲可编译、可测试和可恢复性。

禁止行为：

- 用内存数组假装数据库已经完成。
- 用静态截图或假数据假装界面已接入业务。
- 直接同步SQLite文件代替同步协议。
- 将密码、令牌、端口和密钥硬编码进源码。
- 让UI直接连接云数据库。
- 在没有恢复机制时启用严格应用或网络限制。
- 使用轮询高频扫描所有进程而不考虑功耗。
- 以“以后再处理”为由跳过错误处理、迁移和测试。
- 未经用户授权收集高敏感活动内容。

## 29. 最终完成定义

只有同时满足以下条件，才能称为最终版本：

- 单机离线模式完整可用。
- 日历、待办、项目、四象限和专注系统数据一致。
- 拖拽、快捷键、提醒、重复和搜索达到正式使用水平。
- 应用与网站限制具备白名单、临时允许、紧急解锁和异常恢复。
